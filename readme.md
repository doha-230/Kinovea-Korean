# Kinovea — 한국어(비아스키) 환경 대응 포크

> 원본 [Kinovea/Kinovea](https://github.com/Kinovea/Kinovea) 를 **한국어 Windows(CP949)** 환경에서
> 정상적으로 **빌드·사용**할 수 있게 만든 포크입니다.
> 한글 경로/파일명 영상이 정상 동작하고, **주요 UI가 한국어로 번역**되어 있으며,
> 스포츠 분석 실사용에 필요한 **프레임 스킵 제어**(사용자 on/off · 모션 적응),
> **트래킹 강건성** 개선, **오디오 음량 추출·내보내기**가 포함되어 있습니다.

업스트림 최신 `master` 와 동기화된 상태를 유지하며, 모든 변경은 **Windows x64 Release 빌드와
자동 검사(정적 검사 5종 + 단위 테스트 15종)** 로 검증됩니다.

| 항목 | 상태 |
|:--|:--|

| 배포 산출물 | ① 설치용 단일 `.exe` ② 포터블용 단일 `.zip` |

## 1. 해결한 문제

### 1.1 CP949(한국어) 환경에서 빌드 실패 — **핵심**

| | |
|:--|:--|
| **증상** | 시스템 언어가 한국어인 환경에서 빌드 실패<br>`error CS1010: 상수에 줄 바꿈 문자가 있습니다.`<br>`error CS1003 / CS1002 / CS1519: 토큰 오류` |
| **원인** | 일부 소스가 UTF-8 문자의 **리드 바이트가 유실된 채** 저장됨(예: `©` → `0xA9`, `°` → `0xB0`). 서양 코드페이지에서는 컴파일러가 넘어가지만, **CP949는 그 바이트를 "미완성 한글"로 해석**해 문자열 상수를 깨뜨림 |
| **해결** | **319개** 파일에 UTF-8 BOM 부여 + **72개** 파일의 손상 바이트를 **CP1252 폴백으로 복구** → 전체 **1,263개 소스 파일이 유효한 UTF-8 + BOM** |
| **재발 방지** | `.editorconfig` `charset = utf-8-bom`, `.gitattributes` `* -text` + CI 인코딩 검사 |
| **재현** | `python Tools/normalize_encoding.py .` |

### 1.2 로케일(소수점 기호)에 따른 파일 가져오기 오류

- **TRC/Sports2D** 가져오기가 `float.Parse` 를 **현재 문화권 기준**으로 파싱 → 소수점이 쉼표인
  유럽 로케일에서 값이 깨지거나 예외 발생.
- **해결**: `InvariantCulture` 명시. CI에서 **무문화 파싱 0건**을 상시 검사.

### 1.3 한국어 UI 미번역 (하드코딩 문자열)

- 플레이어/캡처/내보내기 환경설정 패널 등에 **UI 문자열이 코드에 하드코딩**되어
  번역 리소스에 항목 자체가 없었습니다(최신 패널이 통째로 영어).
- **해결**: 하드코딩 UI 문자열 **91건 → 5건**으로 이관(resx 등록 + 한국어 번역),
  한국어 **번역 커버리지 100%** 달성. 남은 5건은 *의도적 허용*(구버전 플러그인 영문 폴백,
  고유명사, 컴파일되지 않는 파일)으로 문서화했습니다.

### 1.4 기계번역 수준의 한글 표기

- 키 **누락은 0건**이었지만 번역 *품질*이 낮았습니다. 예:
  `Cancel`→“취소하다”, 내보내기 메뉴→“퍼지는도표 내보내기”, “궤적 씨 에스 브이…”,
  “틀 비율 결과냅니다:”(Resulting framerate), “종이고정철사판에 복사하십시오”(Copy to Clipboard),
  `Save`→“구하십시오”.
- **해결**: 용어를 정하고 **총 224개 문자열**을 다시 작성했습니다 —
  환경설정·캡처·프레임·클립보드·레이블·키 이미지·트리거·카메라 등.
  같은 유형이 재발하지 않도록 **번역 품질 검사기를 CI 게이트**로 추가했습니다(현재 0건).

### 1.5 추적 실패 시 복구 수단 없음

- 기존 트래커는 검색창 안에서 대상을 놓치면 **이전 위치를 유지한 채 실패**로 종료 →
  빠른 동작(스프린트·점프)에서 추적이 끊기고 되돌리기 어려웠습니다.
- **해결**: 실패 시 **검색창을 1.5배 → 2배로 확대해 재탐색**(최대 400px 한도 내) 후
  가장 좋은 점수를 채택. **정상 성공 경로는 전혀 바뀌지 않습니다.**

### 1.6 Excel에서 한글 CSV 깨짐

- 내보낸 CSV/TXT/JSON이 **BOM 없는 UTF-8** 이라 한국어 Excel이 CP949로 오인해
  한글이 깨져 보였습니다.
- **해결**: 내보내기 텍스트 인코딩을 **사용자가 선택** — `UTF-8` / `UTF-8 (BOM, Excel)` /
  `시스템 기본`. 기존 동작(무BOM UTF-8)이 기본값입니다.

### 1.7 자동 검증 부재

- 업스트림의 테스트 프로젝트(`Kinovea.Tests`)는 **솔루션 밖**에 있어 아무것도 검증되지 않았고,
  일부 헬퍼는 오래된 API를 참조해 컴파일조차 되지 않았습니다.
- **해결**: CI에서 **테스트 프로젝트를 빌드하고 실행**하도록 연결하고 단위 테스트를 추가,
  정적 검사 5종을 게이트로 추가했습니다.

### 1.8 환경설정(export) 저장 버그 2건

오디오 기능 구현 중 발견해 함께 수정했습니다.

| 버그 | 내용 |
|:--|:--|
| `ExportSpace` 미복원 | `ReadXML` 에서 `case "ExportSpace":` 가 `CSVEncoding` 으로 **폴스루**되어 내보내기 좌표계 설정이 **읽히지 않았고**, 그 대입문은 도달 불가 코드였습니다 |
| `ExportImagesInDocuments` 오기록 | 저장 시 export space 값(`WorldSpace` 등)을 **불리언 자리에 기록**하고 있었습니다 |

## 2. 추가·개선한 기능

### 2.1 프레임 스킵 — **사용자가 켜고 끌 수 있습니다**

> 요구사항: "스킵 관련 기능은 사용자가 켜고 끌 수 있어야 한다."

| 제어 | 방법 |
|:--|:--|
| **켜기/끄기 (마스터)** | 환경설정 ▸ **재생** 탭 체크박스 · 단축키 **`Ctrl+Shift+S`** · 인포바 상태 표시 |
| **모드** | 환경설정 ▸ 재생 탭의 **모드 선택**: `자동` / `수동` / `모션 적응` |
| **건너뛸 프레임 수** | 수동 모드에서 **0 ~ 10** (상한 `MaxFrameSkip = 10`) |
| **증감 단축키** | `Ctrl+Shift+↑` / `Ctrl+Shift+↓` |
| **상태 표시** | 인포바에 `Skip off` (꺼짐) 또는 `Skip N` (수동 N프레임) |

- 마스터를 끄면 **수동·자동·모션 적응 스킵이 전부 무효**가 되고 즉시 다음 프레임부터 적용됩니다.
- 설정은 `PlayerPreferences`(XML)에 저장되어 재실행 후에도 유지됩니다.

### 2.2 모션 적응 프레임 스킵 — **정지면 많이, 움직이면 적게**

> 요구사항: "움직임이 없으면 스킵 크게, 움직임이 크면 스킵 적게."

- 최근 프레임에서 **화면의 움직임 양을 측정**해 스킵 수를 자동 결정합니다.
  - **정지 장면** → 최대 10프레임까지 건너뛰어 빠르게 검토
  - **빠른 동작** → 스킵 0 (프레임 단위로 재생해 시간 해상도 보존)
- 측정값은 **경과 시간(ms)으로 나눈 속도**입니다. 단순 프레임 차이를 쓰면
  "스킵↑ → 차이↑ → 스킵↓" 자기참조 진동이 생기기 때문입니다.
- 아직 측정값이 없을 때와 **추적 중에는 스킵하지 않습니다**(연속 프레임 보존).
- **기본값은 `자동`** 이라 기존 동작이 그대로 유지되며, 필요할 때만 켜면 됩니다.

### 2.3 트래킹 강건성 개선

- 검색창 확대 재탐색(1.5× → 2×, 최대 400px) — 1.4절 참고.
- 참고: 업스트림은 이미 **서브픽셀 정밀도**(포물선 보간)를 구현하고 있어 추가 작업이 불필요했습니다.

### 2.4 내보내기 인코딩 선택

- 환경설정 ▸ **내보내기** 탭 ▸ **텍스트 파일 인코딩**: `UTF-8` / `UTF-8 (BOM, Excel)` / `시스템 기본`
- 적용 대상: CSV(궤적·크로노), TXT, JSON, Markdown

### 2.5 오디오 음량 추출·내보내기 🆕

영상의 오디오에서 **시간에 따른 소리 크기**를 뽑아 표로 내보냅니다.
(점프 착지음, 공 충돌음, 발소리 시점을 수치로 확인해 궤적·관절 각도와 대조)

- **위치**: 파일 ▸ 내보내기 ▸ **오디오 음량…**
- **옵션**: 창 크기(10~5000ms, 기억됨) · 형식(**CSV / Excel / TXT / JSON**)
- **열**: `Time (s)` · `RMS (dBFS)` · `Peak (dBFS)` — 0이 최대, 음수가 작음
- 추출은 앱에 **이미 포함된 ffmpeg**(`astats` 필터)로 수행 → 추가 배포물 없음
- **프레임 해상도(약 20ms)로 1회 추출 후 창 단위 집계** → 창을 바꿔도 재추출 없음
- 무음 구간은 `-100 dBFS` 로 기록, **오디오 트랙이 없는 파일**은 안내 메시지로 종료
- 예외 처리: ffmpeg 없음 · 추출 실패 · 시간 초과/취소

## 4. 빌드 · 배포

### 요구 사항
- Windows 10/11 x64
- Visual Studio Build Tools 2022 (MSVC v143, C++/CLI 지원, **.NET Framework 4.8**)
- FFmpeg 의존성 복원(`Refs/FFmpeg`) 및 NuGet 복원

### 빌드
```bat
MSBuild.exe Kinovea.VS2019.sln /t:Build /p:Configuration=Release /p:Platform=x64 /m
```

### 산출물 — 정확히 2개
| 산출물 | 설명 |
|:--|:--|
| `Kinovea-<버전>.exe` | **설치용 단일 실행 파일** (NSIS, 모든 파일 내장) |
| `Kinovea-Portable-<버전>.zip` | **포터블용 단일 압축 파일** (압축 해제 후 설치 없이 실행) |

### 릴리스 자동화
```bash
git tag v2026.2.0
git push origin v2026.2.0
```
→ Windows 빌드 → 설치 파일 + 포터블 압축 생성 → **GitHub Release 자동 발행**
(버전은 태그에서 자동 추출되어 파일명·설치 파일·릴리스명에 일관되게 반영)

## 5. 품질 게이트 (CI)

빌드 **전에** 아래 검사가 실행되며, 하나라도 실패하면 워크플로가 중단됩니다.

| 검사 | 내용 | 기준 |
|:--|:--|:--|
| `Tools/lint/check_encoding.py` | 모든 소스가 **UTF-8 + BOM** | 0건 유지 |
| `Tools/lint/check_csproj_includes.py` | 모든 `.cs`/`.vb` 가 `.csproj`에 등록 | 기준선 파일 |
| `Tools/lint/check_culture_parsing.py` | 무문화 `float/double/decimal.Parse` | 0건 유지 |
| `Tools/i18n/scan_hardcoded_strings.py` | UI 문자열 하드코딩 | 기준선 파일 |
| `Tools/i18n/check_translations.py --lang ko` | 한국어 번역 키 누락 · `{0}` 플레이스홀더 일치 | 0건 |
| `Tools/i18n/check_translation_quality.py` | 기계번역 흔적(음차·동사형 라벨·미번역·오역 용어) | 기준선 파일 (현재 **0건**) |

이후 **본 빌드 → 테스트 프로젝트 빌드 → 단위 테스트 실행 → 인스톨러/포터블 생성**이 진행됩니다.

단위 테스트는 **실패 개수를 종료 코드로 반환**하므로 CI가 실제로 실패합니다.
현재 **15종**이 실행됩니다 — 모션 적응 지표 4종 + 오디오 음량 파서·집계 11종.

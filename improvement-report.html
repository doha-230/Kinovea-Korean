1. 한글 PC에서 빌드가 실패하는 문제

증상 시스템 언어가 한국어인 PC에서 빌드하면 컴파일이 실패.
CS1010: 상수에 줄 바꿈 문자가 있습니다., CS1003, CS1519 등의 오류가 여러 파일에서 발생.
원인 소스 파일 100여 개가 손상된 인코딩으로 저장되어 있었다. 원래 UTF-8이어야 하는데, 한글·특수문자의 앞부분 바이트가 빠진 채 Latin-1(Windows-1252)처럼 변환된 상태였다.

예) © → 0xA9, ° → 0xB0, × → 0xD7

서양(라틴) 코드페이지 PC에서는 그대로 컴파일되고, 한글(CP949) PC에서는 해당 바이트를 미완성 한글 글자로 해석해 문자열이 깨지며 빌드가 실패했다.
해결 손상된 소스를 올바른 UTF-8로 복구하고, 모든 소스 파일에 UTF-8 BOM을 일괄 추가해 컴파일러가 코드페이지와 무관하게 파일을 UTF-8로만 해석하도록 했다.
그 결과 한국어 Windows에서도 전체 솔루션(Release x64) 빌드가 성공했다.

이 과정에서 빌드에 필요한 도구도 함께 준비했다.

  • Visual Studio Build Tools 2022 — MSVC v143, C++/CLI 지원, .NET Framework 4.8
  • FFmpeg 8.1.2 라이브러리 (Refs/FFmpeg)
  • NuGet 패키지 복원

2. 한글 경로/파일명에서 영상을 열지 못하는 문제

증상 동영상 파일명이나 폴더 경로에 한글이 들어가면 에러가 나고 영상을 열 수 없었다.
점검 결과 영상을 여는 핵심 경로(FFmpeg 연동부)는 이미 유니코드를 올바르게 처리하고 있었다. VideoReaderFFMpeg.cpp는 .NET UTF-16 문자열을 UTF-8로 변환해 avformat_open_input에 넘기고, MJPEGWriter.cpp도 저장 시 동일하게 UTF-8 버퍼를 사용.

다만 1번 문제의 인코딩 손상 때문에 소스가 깨져 빌드가 되지 않았고, 정상 동작 여부를 확인할 수 없었다. 인코딩을 복구해 빌드가 되는 상태로 만든 뒤 검증했다.

검증 내용 (빌드된 실행 파일로 테스트)

  • 한글 폴더에서 Kinovea 실행 — 정상
  • 한글 폴더 안의 한글 이름 영상 열기 — 정상 (로그에 오류 없음)
  • 한글 파일명·한글 경로 조합의 저수준 열기 테스트 — 전부 Success

결론적으로 한글 경로/파일명 자체는 원래 지원이 가능한 범위였고, 인코딩 손상이 이를 가로막고 있었던 것.

3. 프레임 스킵 기능 추가

기존에는 재생 속도를 2배까지만 조절할 수 있었고, 트래킹 중에는 프레임을 건너뛸 수 없었다(트래커가 연속 프레임을 요구하기 때문). 사용자가 배속과 프레임 스킵을 각각 지정할 수 있게 했다.

추가된 기능

  • 배속 슬라이더 옆에 FrameSkip: 입력란 추가. 0이면 끔, 숫자를 넣으면 1회 렌더링마다 그만큼 프레임을 건너뜀.
  • 핫키 명령 IncreaseFrameSkip / DecreaseFrameSkip 추가.
  • 트래킹 중에도 동작 — N번째 프레임마다 트랙을 확장하는 서브샘플링 방식.
  • 설정값은 저장되어 재실행 후에도 유지.
  • 입력란을 마우스로 벗어나도 입력한 값이 덮어써지지 않도록 처리.
참고 프레임을 너무 많이 건너뛰면 물체가 템플릿 검색창 밖으로 나가 추적이 실패할 수 있다. 추적 알고리즘은 교체하지 않았고 기존 템플릿 매칭 트래커를 그대로 사용한다.
